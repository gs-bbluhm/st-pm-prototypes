Grouped Ask Starters

Prototype of the "/Starters" panel in the Exec Dashboard Ask box. Two tabs, Cross-account first, then Account. A starter lands in the ask bar with the part to fill in brackets. Which starters appear follows the person's role. Click a starter, or type / in the ask bar.

Design notes for Omri and Gilad

1
Frontend + backend

The role picks the list; there is no switch

Show the starters for the person's Staircase role (User, Manager, Admin) from the starter config. The dashed control above the mock is only for previewing each role. Later, not MVP: admins could see every starter.

2
Frontend

Two button tabs, Cross-account first

Cross-account opens by default because the Exec Dashboard is a cross-account surface. Account holds the one-account starters (prep, catch up, risk, handoff). Three starters show per tab; the rest sit behind Show more. The count on each tab is the total. No search box: typing / in the ask bar does the finding.

3
Frontend

Brackets mark what to fill

A starter lands in the ask bar with [write the account name] or [teammate name, tier or all accounts] selected, so typing replaces it. Send stays off while a bracket is left. The text in the bar is exactly what runs; there is no hidden prompt.

4
Frontend

Slash commands and short instructions

Typing / opens the panel and filters it as you type (/ren shows the renewal starters); Enter picks the top match. Two plain steps sit at the bottom of the panel. The full text of every starter is in the engineering spec, not in the panel.

5
Backend

Starters as config, not code

Serve the list from a config so PM can change wording without a deploy, and hide a starter in an org where its fields are empty (no risk levels, no expansion analysis).

{
  "name": "Renewal game plan",
  "tab": "cross_account",     // or "account"
  "roles": ["user"],
  "tier": "core",             // core shows; more sits behind Show more
  "template": "Sort active accounts for [teammate name, tier or all accounts] renewing in the next 90 days ...",
  "requires": ["customer.risk.risk_level", "expansion_opportunity"]
}
6
Later, not MVP

Pickers in place of brackets

An account typeahead that fills the bracket and sends scope.account_ids (already in the request contract), and a scope chip for me, a teammate, a tier or all accounts. Brackets ship first; pickers replace them later with no change to the starter text.
